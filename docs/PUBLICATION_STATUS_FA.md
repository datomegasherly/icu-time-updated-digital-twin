# وضعیت آماده‌سازی کد برای انتشار مقاله

**مالک اعلام کرده مخزن GitHub به نشانی https://github.com/datomegasherly/icu-time-updated-digital-twin عمومی شده و مجوز MIT انتخاب شده است. محتوای آنلاین مخزن هنوز مستقل تأیید نشده؛ نسخه مستقل Zenodo نیز ثبت نشده است.**

- ۴۶ فایل کد/تنظیمات اصلی از آرشیو پروژه و پچ‌های اجراشده، بدون تغییر علمی، بسته‌بندی شده‌اند.
- هفت اثرانگشت SHA256 مربوط به Stage 8F دقیقاً با فایل‌های فعلی منطبق است.
- هیچ CSV سطح بیمار، DuckDB، فایل مدل، داده خام، رمز یا توکن به بسته اضافه نشده است.
- فایل‌های تاریخچه‌ای مراحل قبلی برای ردیابی قرار دارند؛ تحلیل اصلی Stage 7E تا Stage 8D است.
- کدهای Stage 8F و 8G نیز برای مستندسازی قفل پروتکل و محدودیت‌های اعتبارسنجی آمده‌اند؛ نه برای ادعای تأیید مستقل مدل.
- پذیرش/اصلاحیه اخلاق پژوهش باید براساس تصمیم واقعی دانشگاه تنظیم شود؛ نمی‌توان صرفاً از نبود کد، معافیت رسمی را نتیجه گرفت.

## پیش از انتشار
1. روی سیستم ویندوز خودتان دستور `python tools\verify_release.py` را اجرا کنید.
2. پس از نصب نیازمندی‌ها `python tools\smoke_test.py` و `python -m pip freeze > environment_authors.txt` را اجرا کنید؛ فایل environment_authors را از جهت مسیر یا نام بسته‌های خصوصی بررسی کنید.
3. مجوز MIT در مخزن انتخاب شده؛ فایل LICENSE موجود در ریشه گیت‌هاب را حفظ کنید و مطمئن شوید حقوق انتشار کد با نویسندگان و دانشگاه تطبیق دارد.
4. بعد از تأیید نمایش همه فایل‌های استخراج‌شده در مخزن عمومی و در صورت تمایل ثبت Zenodo، بیانیه Code Availability مقاله را با آدرس واقعی و شناسه نسخه موجود به‌روزرسانی کنید.
5. نسخه واقعی دیتاست‌های استفاده‌شده، و وضعیت اخذ قانونی داده‌ها توسط پژوهشگران مجاز را مستند کنید.
6. مغایرت مربوط به مرز زمانی پیامد در پروتکل آینده را با اصلاحیه نسخه‌دار رفع کنید.

**در GitHub کل `project(2).zip` و همچنین پوشه `outputs`، مدل‌های `pkl`، فایل‌های `csv` فردی یا DuckDB را منتشر نکنید.**
